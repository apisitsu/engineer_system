# การออกแบบระบบจัดการเอกสารและการออกหมายเลขเอกสารอัตโนมัติ (Document Management System Design)

เอกสารฉบับนี้คือการออกแบบระบบเพื่อนำข้อมูลจากไฟล์ `DOCUMENTS.xlsx` มาพัฒนาเป็นระบบจัดการเอกสารแบบรวมศูนย์ (Centralized System) โดยมีจุดประสงค์หลักเพื่อออกหมายเลขเอกสารอัตโนมัติ ป้องกันการซ้ำซ้อน และจัดการลิงก์เอกสารอย่างมีประสิทธิภาพ

## 1. ภาพรวมของระบบ (System Overview)
*   **เป้าหมาย:** เปลี่ยนจากการบันทึกมือบน Excel เป็นระบบ Web Application ที่มีฐานข้อมูลรองรับ
*   **ฟีเจอร์หลัก:**
    *   สร้างเลขที่เอกสารอัตโนมัติ (Auto-running number)
    *   รูปแบบเลขเอกสาร: `[ตัวย่อเอกสาร]-[00000-99999]` เช่น `MEMO-00001`
    *   รองรับการเพิ่มประเภทเอกสารใหม่ (ตัวย่อใหม่) ได้อย่างอิสระโดยไม่ต้องแก้โค้ด
    *   ตรวจสอบและป้องกันการออกเลขเอกสารซ้ำซ้อน (Concurrency Control)
    *   จัดเก็บและจัดการลิงก์ (URL) สำหรับเข้าถึงไฟล์เอกสารจริง

## 2. โครงสร้างฐานข้อมูล (Database Design)
เพื่อให้ระบบสามารถเพิ่มตัวย่อใหม่ได้อิสระ เราจะแบ่งฐานข้อมูลออกเป็น 2 ตารางหลัก (Tables) ดังนี้:

### Table 1: `DocumentTypes` (ตารางเก็บประเภทและตัวย่อเอกสาร)
ตารางนี้ใช้สำหรับกำหนดประเภทเอกสาร และติดตามว่าหมายเลขล่าสุดของประเภทนั้นๆ คือหมายเลขอะไร
*   `id` (INT, Primary Key) - รหัสอ้างอิง
*   `prefix` (VARCHAR, Unique) - ตัวย่อชื่อเอกสาร เช่น "PO", "INV", "MEMO"
*   `name` (VARCHAR) - ชื่อเต็มของประเภทเอกสาร
*   `current_number` (INT) - หมายเลขเอกสารล่าสุดที่ถูกสร้าง (เริ่มต้นที่ 0)
*   `is_active` (BOOLEAN) - สถานะการใช้งาน (เปิด/ปิด)

### Table 2: `Documents` (ตารางเก็บข้อมูลเอกสารจริง)
ตารางนี้คือตารางที่จะมาแทนที่ข้อมูลในไฟล์ `DOCUMENTS.xlsx` ของคุณ
*   `id` (INT, Primary Key) - รหัสอ้างอิง
*   `document_no` (VARCHAR, Unique) - หมายเลขเอกสารที่ออกสำเร็จ เช่น "MEMO-00001" (ตั้ง Unique ป้องกันซ้ำ)
*   `type_id` (INT, Foreign Key -> DocumentTypes.id) - อ้างอิงประเภทเอกสาร
*   `title` (VARCHAR) - ชื่อเรื่องเอกสาร
*   `document_link` (TEXT) - ลิงก์สำหรับกดเข้าไปดูเอกสาร (Google Drive, SharePoint, etc.)
*   `created_by` (VARCHAR) - ผู้สร้างเอกสาร
*   `created_at` (DATETIME) - วันที่สร้างเอกสาร

## 3. ลอจิกการออกหมายเลขเอกสารอัตโนมัติ (Auto-Numbering Logic)
เมื่อผู้ใช้งานต้องการเพิ่มเอกสารใหม่ ระบบจะทำงานตามขั้นตอนต่อไปนี้ (ควรใช้ Database Transaction เพื่อป้องกันการแย่งกันกดสร้างพร้อมกัน):

1.  **รับค่า:** ผู้ใช้เลือกประเภทเอกสาร (เช่น เลือก "MEMO") และกรอกรายละเอียด
2.  **Lock & Read:** ระบบเข้าไปอ่านค่า `current_number` จากตาราง `DocumentTypes` ที่ `prefix = 'MEMO'` พร้อมทำการ Lock แถวนี้ไว้ชั่วคราว
3.  **Calculate:**
    *   นำ `current_number` + 1
    *   จัดรูปแบบหมายเลขให้ครบ 5 หลัก (Zero-padding) เช่น ถ้าระบบคำนวณได้ `1` ให้แปลงเป็น `00001`
4.  **Format:** นำ Prefix มาต่อกับหมายเลข เช่น `MEMO` + `-` + `00001` = `MEMO-00001`
5.  **Save & Update:**
    *   บันทึกข้อมูลเอกสารใหม่ลงตาราง `Documents` โดยใช้เลข `MEMO-00001`
    *   อัปเดตค่า `current_number` ในตาราง `DocumentTypes` ให้เป็นเลขล่าสุด
    *   Commit Transaction (ปลดล็อค)

## 4. ข้อดีของการออกแบบนี้
*   **ป้องกันเอกสารซ้ำซ้อน (No Duplicates):** การแยกตารางเก็บ `current_number` และการใช้ฐานข้อมูลแบบ Relational พร้อมทำ Unique Index ที่คอลัมน์ `document_no` จะรับประกันได้ว่าเลขจะไม่มีทางซ้ำกันแน่นอน
*   **ยืดหยุ่นสูง (Scalability):** หากในอนาคตมีเอกสารประเภทใหม่ (เช่น "PR") แอดมินสามารถเพิ่มเรคคอร์ดใหม่ในตาราง `DocumentTypes` (กำหนด `prefix = 'PR'`, `current_number = 0`) ได้เลยผ่านหน้าจอตั้งค่า โดยที่โปรแกรมเมอร์ไม่ต้องแก้โค้ด
*   **พร้อมสำหรับการทำ Migration:** ข้อมูลเก่าจากไฟล์ `DOCUMENTS.xlsx` สามารถนำมาเขียน Script เพื่อ Import เข้าตาราง `Documents` ในฐานข้อมูลระบบใหม่ได้อย่างเป็นระเบียบ

## 5. เทคโนโลยีที่แนะนำ (Recommended Tech Stack)
*   **Database:** MySQL, PostgreSQL, หรือ SQL Server (เหมาะสำหรับการทำ Transaction Lock)
*   **Backend API:** Node.js (Express), Python (FastAPI/Django), PHP (Laravel) หรือ C# .NET
*   **Frontend:** React, Vue.js, หรือ HTML/CSS/JS ธรรมดาสำหรับสร้างฟอร์มกรอกข้อมูลและตารางแสดงผล
