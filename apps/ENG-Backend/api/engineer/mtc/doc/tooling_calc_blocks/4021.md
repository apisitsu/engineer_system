## WHEEL (4021-05) — range table

Workbook `砥石・クイル` sheet: `巾min | 巾max | 内径min | 内径max → WHEEL(4021-05) · QUILL(4021-03) · QUILL BOLT(4021-04)`.
Pick the row where `巾min ≤ W ≤ 巾max` **and** `内径min ≤ ID ≤ 内径max`.

Config WHEEL: `A = W · B = W · C = ID · D = ID`, search rules
`A→dim_a tol_plus 0` (`dim_a ≤ W`), `B→dim_b tol_minus 0` (`dim_b ≥ W`),
`C→dim_c tol_plus 0` (`dim_c ≤ ID`), `D→dim_d tol_minus 0` (`dim_d ≥ ID`)
= `dim_a ≤ W ≤ dim_b` and `dim_c ≤ ID ≤ dim_d`, with `dim_a..d` = 巾min/巾max/内径min/内径max.

**WHEEL verdict: MATCH** — the `+0` containment pattern reproduces the workbook range table exactly.

## QUILL (4021-03) / QUILL BOLT (4021-04) — deliberate divergence

The workbook table also assigns QUILL and QUILL BOLT off the **same (W, ID) range**. Config does **not**
formula-drive these: they ship as **cn-map / lookup-only** (`20260821c_ksb80_quill_and_bolt.js`, `dim_* NULL`
by design). Audit C-1/C-2: the real selection chain is `work → WHEEL (ID×W) → QUILL BOLT (per wheel size) →
QUILL (per bolt fit)` — not expressible as a per-part formula, so the factory plan pins it per C/N.

**Not a defect** — documented in `.claude/rules/tooling-select.md` and the audit doc.
