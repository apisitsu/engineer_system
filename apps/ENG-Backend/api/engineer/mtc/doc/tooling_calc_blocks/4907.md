## Verdict (revised 2026-08-28 after coverage analysis)

**NOT ENCODED by design — and a formula is NOT worth building here.**

The 4 LOADER formulas are `-999` sentinels; selection runs on `tooling_partno_map`, **keyed by
`parts_no`** (not `cn`): 442 pinned rows — 4907-01 ×59, 4907-03 ×57, 4907-05 ×164, 4907-06 ×162.

Checked against `lpb.eng_r_pi_tool` (process 1241, the only one 4907 runs at):

| family | plan C/N | parts_no pins | shelf rows |
|---|---|---|---|
| 4907-01 LOADER END BLOCK | 59 | **59** | 20 |
| 4907-03 LOADER FINGER CHUCK | 57 | **57** | 9 |
| 4907-05 LOADER | 164 | **164** | 2 |
| 4907-06 LOADER | 162 | **162** | 2 |

**Every 4907 tool the shop plans is already pinned** (59/59, 57/57, 164/164, 162/162). The disabled
formulas have **zero effect on any planned part**. 4907-05/06 have 2 drawings each — the shop's pick
between them is not a dimensional formula. 4907-01/03 do have a ball-dia band table (above), but they
are already fully pinned too.

Wiring the band rule would need ~90 shelf rows' `dim_a`/`dim_b` populated by hand from imperfect PDF
band tables, on prod, to serve only hypothetical unpinned parts — negative value. **Leave on the
parts_no map.** This is the same deliberate pattern as XD-8 STOPPER, FTL PUSHER OP1, KS-400B1 PLUG A/B.

The conformance page's NOTE flag should read: *"runs on parts_no-map (100 % of planned C/N); sentinel
formulas are the intended disabled-fallback — not a defect."*
